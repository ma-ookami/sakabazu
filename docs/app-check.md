# App Check の設定(酒場図)

作成: 2026-10-18 / 対象: Firebase プロジェクト `sakabazu`

---

## 1. なぜ必要か

### 酒場図のつくり
酒場図は、ブラウザから直接 Firebase(データベース Firestore とログイン)を呼び出す作りになっている。
そのため、Firebase の接続情報(`firebase-config.js` の apiKey など)はページの中に公開されている。
これは Firebase の正しい使い方で、情報そのものを隠す必要はない。

### 守れているもの:データの中身
「誰がどのデータを読めるか、書けるか」は `firestore.rules`(ルール)で守っている。

- 自分のリストは自分だけが書ける
- 飲み友は、承認した相手のリストを読めるだけ

### 守れていないもの:アクセスの「量」と「出どころ」
ルールは「このアクセスは許可された操作か」しか見ていない。
「本物の酒場図のページから来たか」「プログラムで大量に送られていないか」は見ていない。
接続情報は公開されているので、悪意のある人が自作のプログラムから次のようなことをできてしまう。

| 起こりうること | 影響 |
|---|---|
| 匿名アカウントを大量に作り、空のリストを大量に作る | Firebase の無料枠を使い切る。従量課金なら請求が発生する。上限に達すると、本物の利用者もアプリが使えなくなる |
| 飲み友コードを総当たりで調べる | 申請が大量に届く(迷惑)。読み取り回数を消費する |
| 正しい操作を、ものすごい回数くり返す | 上と同じく、無料枠や料金に響く |

---

## 2. App Check とは

**「本物の酒場図のページから来たアクセスか」を Firebase が確かめる仕組み。**

1. 酒場図のページが開かれると、裏で Google の reCAPTCHA Enterprise が、ブラウザの様子から人間による普通の利用かを判定する。
   - 画像を選ばせるような操作は一切ない。利用者からは見えない。
2. 本物と判定されると、ページに短時間有効な「証明書(トークン)」が渡される。
3. ページは Firebase を呼ぶたびに、この証明書を一緒に送る。
4. Firebase は証明書のないアクセスや偽物のアクセスを断る(「適用」した後)。

接続情報を知っていても、自作のプログラムからは証明書を手に入れられないので、アクセスできなくなる。

---

## 3. 何ができるようになるか

### できるようになること
- ページ以外(自作プログラム・ボット)からの Firestore へのアクセスを断れる。
- 大量アカウント作成やデータの荒らしで、無料枠を使い切られる危険が大きく下がる。
- Firebase の画面で「確認済みのリクエスト / 確認されていないリクエスト」の数が見えるようになる。不正なアクセスが来ているかどうかも分かる。

### できないこと(別の対策が必要)
| 守れないもの | 理由・別の対策 |
|---|---|
| データを読み書きできる人の制限 | これはルール(`firestore.rules`)の役目。App Check はルールの代わりにはならず、両方そろって安全になる |
| 本物のブラウザを使った、手作業に近い悪用 | 本物のページから来るため、証明書が取れてしまう。ルールで被害を小さくする |
| お店検索の中継(Cloudflare Worker)と Google の店検索の料金 | App Check の対象外。Google Cloud で利用上限・予算アラートを別に設定する |
| ログイン(Authentication)そのもの | 今回は Firestore だけが対象 |

## 5. 運用メモ

- **様子の見方**:Firebase → App Check → API → Cloud Firestore のグラフ。
  - 「確認されていないリクエスト」が急に増えたら、ページ以外からのアクセスが来ているしるし。
- **問題が起きたら**:同じ画面で「適用」を解除すれば、すぐ元の状態に戻る。データは消えない。
- **手元のパソコンで試すとき(localhost)**:
  - localhost では「デバッグトークン」を使う設定になっている(`js/cloud.js`)。
  - 適用後は、ブラウザのコンソールに出るデバッグトークンを Firebase → App Check → アプリ →「デバッグトークンを管理」に登録しないと、データが読めない。
- **料金**:reCAPTCHA Enterprise の判定は月1万回まで無料。個人利用なら超えない見込み。
- **公開URLを変えるとき**:新しいドメインを、1 のキーのドメインにも追加する。追加しないと判定に失敗し、適用後はアプリが動かなくなる。

## 6. 関連する対策(まとめ)

| 対策 | 守るもの | 状態(2026-10-18) |
|---|---|---|
| `firestore.rules` | 誰が何を読めるか・書けるか(リストは本人だけ、飲み友は承認制で読むだけ) | 更新済み。Firebase への貼り付けが必要 |
| App Check | アクセスが本物のページから来ているか | キー設定済み。様子見のあと「適用」 |
| Google Cloud の利用上限・予算アラート | Google の店検索(Places API)の料金 | 未設定(Google 検索を有効にするときに設定する) |
