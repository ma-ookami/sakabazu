# 酒場図の開発で得た設計の学び

作成: 2026-10-18

酒場図の機能づくりと修正で、指示がこちら(Claude)の案より良かったもの・発想が新しかったものを集めた。
「何を言ったか」「こちらの案はどうだったか」「なぜ良かったか」「今後どう生かすか」の順に書く。

---

## 1. 仕組みそのものを見直した指示

### 1-1. 「グループって考え方があってないのかも」→ 飲み友(1対1)
- **指示**:飲み仲間でリストを共有する「グループ」ではなく、1人1つのリストを持ち、友達とだけつながる形に。
- **こちらの案**:グループの使い勝手(表示の切り替え・メンバー管理)を細かく直し続けていた。
- **なぜ良かったか**:実際の飲みの誘いは「誰か1人と、今日どこ行く?」がほとんど。グループは画面も管理も複雑にしていた。
  - あとで分かったこと:グループの「誰でも参加できる」仕組みが、リストを乗っ取られる穴の元になっていた。考え方を変えたことで、安全面もまとめて整理できた。
- **生かし方**:細部を直す前に「その仕組みは、実際の使われ方に合っているか」を疑う。

### 1-2. 「シェアは『今日どこ行く?』の中だけのほうが分かりやすいか」
- **指示**:飲み友の店が混ざるのは、店を決めるときだけ。リスト・地図・カレンダーは自分の記録帳にする。
- **なぜ良かったか**:「今見ているのは誰の店か」で迷わなくなる。共有する範囲を、目的(決める)にしぼった。
- **生かし方**:共有・公開の範囲は、使う場面で区切る。どこでも混ぜると分かりにくくなる。

### 1-3. 飲み友を承認制に
- **指示**:「飲み友追加に承認があればいいのでは?」
- **こちらの案**:コードを作り直せるようにする、という対症療法を考えていた。
- **なぜ良かったか**:コードが広まっても安全で、「相手が認めたら見える」という説明も分かりやすい。安全と分かりやすさを同時に満たした。
- **生かし方**:安全対策は、利用者に意味が伝わる形(承認・確認)にできないかを先に考える。

## 2. 実際の使われ方から出た指示

### 2-1. 「いままでお店探しは URL を LINE に貼って…」
- **指示**:ふだんの店の決め方(ホットペッパーや Google のリンクを LINE で送り合う)を、そのまま取り込みたい。
- **なぜ良かったか**:新しい習慣を覚えてもらうより、すでにある習慣の続きにしたほうが使われる。
- **生かし方**:機能を考える前に「今は何で代わりにやっているか」を聞く。

### 2-2. 「検索フォームに URL が入れられるのが分かりづらい原因か? 別入り口でもいい」
- **こちらの案**:1つの検索欄で店名も URL も受け付ける「賢い入力欄」にしていた。
- **なぜ良かったか**:1つで何でもできる欄は、できることが見えない。入口を分けると、その操作があることが伝わる。
- **生かし方**:便利さのために機能をまとめるときは、それで「見つけにくく」なっていないか確かめる。

### 2-3. 「行きたいで行ったを押すと、今日の日付に入るのが違う」
- **指示**:「そういえば行ったな」と後から記録することも多い。
- **こちらの案**:「行った=今日」と決めつけていた。
- **なぜ良かったか**:記録はその場でつけるとは限らない。結果、「今日 / 日付を選ぶ / 覚えてない」に。
- **生かし方**:記録系の機能は「後から思い出して入れる」場合を必ず考える。

### 2-4. 決定の流れ:「2人ともOK以外から選ぶこともある」「ある時間でリセット?」
- **なぜ良かったか**:
  - 「2人ともOK」はおすすめ。でも決定はどの店からでもできる。おすすめと強制を分けた。
  - 「いつ消えるか」を問われたことで、日付の区切りを朝5時にできた。夜中に飲んでいる最中に候補が消えない。
- **生かし方**:自動で何かが起きる機能は「いつ・何をきっかけに」を、生活の時間感覚で決める。

### 2-5. 「今日どこ行く?で『そういえば自分もここ行った、行きたかった』ってときに入れられればいい」
- **こちらの案**:リストに「自分のリストに取り込む」ボタンを置いていた。
- **なぜ良かったか**:そう思うのは、相手の店を見ている「その場」。気づいた場所で、すぐ済ませられる。
- **生かし方**:操作は、使う人が思い立つ場所に置く。別の画面に取りに行かせない。

## 3. シンプルさと「残すべきもの」

### 3-1. 「決める画面がごちゃごちゃ」→「最初のボタンが出ていたのはシンプルでおしゃれだった」
- **こちらの案**:今日の候補・絞り込み・候補一覧を全部1画面に並べた。2回作り直しても、情報が多すぎた。
- **指示**:大きな「今日どこ行く?」ボタン1つに戻し、中身は押した先に。
- **なぜ良かったか**:入口の画面は「何をすればいいか」が1つだけ見えればいい。細かい操作は1段奥でかまわない。
- **生かし方**:入口の画面に置くものは、まず1つ。足すときは理由を言えるものだけ。

### 3-2. 「だるまは目印なのでなくさないでほしい」「ルーレットは遊び心があってよかった」
- **こちらの案**:すっきりさせるため、だるまを消し、ルーレットをサイコロの一発表示にした。
- **なぜ良かったか**:だるまやルーレットは、アプリの顔であり楽しさ。「不要な飾り」ではなく、使い続けたくなる理由そのもの。
- **生かし方**:整理するときは「機能」だけでなく「愛着・遊び心」も残す対象として見る。

### 3-3. カードを小さく:「タグは不要、評価は時間の横、行った日も不要」「ジャンルは出して」
- **なぜ良かったか**:一覧のカードに要るのは、選ぶときの判断材料だけ。
  - ジャンル:ラーメンか居酒屋か分からない → 要る
  - 行った日・特徴タグ → 選ぶときには使わない → 要らない
- **生かし方**:一覧に出す情報は「その場面で何を判断するか」で選ぶ。詳細に置けば十分なものは詳細へ。

---

## 4. 操作の手段の選び方

### 4-1. 「行ったはスワイプより簡単なので、スワイプ不要?」「戻すはあまり使わないのでスワイプに」
- **なぜ良かったか**:使用頻度で、操作の見え方を決めた。
  - よく使う(行った・外す)→ 見えるボタン
  - たまに使う(行きたいに戻す)→ 隠れた操作(スワイプ)
  - 「…」メニューは、何が入っているか見えない
- **生かし方**:操作ごとに「どれくらい使うか」を決めてから、ボタン・スワイプ・メニューを割り当てる。

### 4-2. 「本命の絞り込みを最初から出して。提灯が本命ボタンだと分かる」
- **なぜ良かったか**:絞り込みボタンが「提灯=本命」の説明書の役目をする。説明文を足さずに意味を伝えた。
- **生かし方**:隠れがちな機能は、関連する場所に常に出しておくことで「教える」ことができる。

## 5. 世界観と見た目

### 5-1. 「炎を提灯にして。提灯がともるほうが雰囲気がある」
- **こちらの案**:🔥(熱量)。
- **なぜ良かったか**:酒場図の世界観(赤提灯・暖簾)に合い、「灯りがともる=特別な店」という比喩が自然。
- **生かし方**:印やアイコンは、一般的な記号よりも、そのアプリの世界にある物から選ぶ。

### 5-2. 色の意味の一貫性
- **アイコンと色の重なりの指摘**:「アイコンが赤いと『行った』と被る」「紺だと次は行きたいの赤と被るのでは?」
- **最終形**:「薄い紺(行った)・薄い赤(行きたい)」で塗りをそろえ、アイコンには白いふち。
- **「リストに1とつくのはなぜ?」**:意味の薄い赤い数字が、お知らせのように見えていた。赤い印はお知らせ専用にした。
- **生かし方**:色には意味を1つだけ持たせる。同じ色を別の意味で使わない。

### 5-3. 「とどこ行く?に名前が出るのが違和感」「名前をアイコンにしたらすっきりする?」
- **なぜ良かったか**:長い名前の文字は画面を重くする。人を表すのはアイコンで十分。
- **生かし方**:人・物を何度も表示するときは、文字より記号(アイコン)で見せられないか考える。

---

## 6. 細かい違和感を見逃さない

次のような「小さな気になる点」の指摘が、結果的に大きな品質の差になった。

- 開いたときに画面サイズが変わるような動き → 書体の入れ替わりと、読み込み中の仮の枠の形が原因だった
- 「戻る」ボタンに枠が出る → 画面を開くときの自動フォーカスが原因だった
- URL で登録を押すと画面がアップになる → iPhone の入力欄の自動拡大が原因だった
- ルーレットの結果が、ボタンで隠れている
- 評価の丸が楕円になっている
- 詳細ページの余白が多すぎる

**生かし方**:「なんとなく気になる」は、たいてい原因がはっきりしたバグか設計ミス。後回しにせず、その場で原因まで調べる。

---

## 7. まとめ:今後の開発の原則

1. 細部を直す前に、仕組みが実際の使われ方に合っているかを疑う(グループ → 飲み友)。
2. 今ある習慣(LINE で URL を送る、後から思い出して記録する)の続きとして作る。
3. 共有の範囲は、使う場面で区切る(共有は「決める」ときだけ)。
4. 入口の画面は1つのことだけ。愛着や遊び心(だるま・ルーレット)は削らない。
5. 一覧に出すのは、その場で判断に使う情報だけ。
6. 操作は使用頻度で、ボタン・スワイプ・メニューを決める。
7. 操作は、思い立ったその場所に置く。
8. 印や色は、世界観に合わせ、意味を1つに保つ。
9. 安全対策は、利用者に意味が伝わる形にする(承認制)。
10. 小さな違和感は、その場で原因まで追う。
